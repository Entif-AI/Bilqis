# Checkpoints, branching and recovery

Each run begins with a genesis checkpoint, then checkpoints at every tranche boundary and at a requested early stop. A checkpoint directory contains `state.pt` and `receipt.json`. The tensor payload contains model weights, optimizer state, PyTorch RNG state, curriculum state, per-stage example counters, config and parent checkpoint ID. The receipt binds the payload hash, model-state hash, token-ABI hash, architecture, parameter count, precision recipe, exposure/token counts and cost buckets. The run's `latest.json` is a convenience pointer, not authority over a mismatching receipt.

Checkpoint names are step-local IDs such as CP-0000002. Their globally unique identity is the run/config namespace plus payload hash, not the short name alone. Parent IDs remain within that run lineage; a branch must also carry the parent run identifier and receipt hash in its external lineage manifest. Do not merge two parents' short names merely because they both say CP-0000002.

To resume, first verify the receipt and SHA-256 of `state.pt`. Use `torch.load(..., weights_only=True)` on trusted package checkpoints. The runner rejects a config mismatch or changed state identity. A same-config interrupted run was tested against an uninterrupted run and produced the same final model tensor hash in this observed CPU environment. Wall-clock cost naturally differs and is not part of the tensor equivalence assertion. Replaying an optimizer step twice is never a valid recovery strategy.

Use a fresh output directory for a resumed child. Copy or reference its parent run manifest; do not overwrite prior checkpoint bytes. If a crash leaves a directory without a complete matching receipt, quarantine that directory and resume from the preceding complete checkpoint. The current file writer uses atomic replacement for JSON, but a whole checkpoint directory is not atomically committed as one filesystem transaction. An interrupted partial directory is therefore invalid until checked, not automatically the latest recovery point.

For an intervention branch, the clean parent checkpoint contains frozen weights, optimizer state, token ABI and teacher state before the intervention. Fork sibling output directories. A deliberate change of curriculum/representation requires a versioned child config and a branch adapter that changes only the authorized fields after preserving the parent evidence. The simple `--resume` command intentionally rejects such config changes. It should not be weakened into a blanket mismatch bypass. The delivered `bilqis_ref.fork` adapter implements this boundary. It permits representation, teacher-policy, assistance and remaining-budget changes, preserves optimizer state, and rejects architecture or optimizer changes. Its receipt binds the parent receipt and new config. A switch to or from isomorphic token coordinates is rejected unless a specialized embedding/optimizer permutation is supplied. A Bilqis-to-CNL fork was tested; this is an engineering check, not a causal effect estimate.

Learning exposure counters include repeated/rehearsed examples. New checkpoint files, teacher calls and evaluation probes carry their own counters. Parent hashes establish lineage and integrity, not scientific truth or permission to disclose. A checkpoint that passed a code test can still contain a scientifically uninformative student.

The production package itself is independently protected by full recoverable Drive checkpoints. That is separate from the student's optimizer checkpoints. Neither a local ZIP nor a short checkpoint ID proves remote persistence; external receipts identify the actual remote objects.

## Probe-boundary crash recovery

A tranche emits a `CP-0000002-preprobe`-style checkpoint before DEV evaluation. Its `pending_probe` field obliges recovery to finish that probe before another optimization step. The post-probe checkpoint then records the promotion/remediation decision. A test resumes from the pre-probe boundary and compares final tensor hashes to uninterrupted execution. Both ordinary and pre-probe recovery tests passed on the observed CPU environment. Code identity is bound by the package engineering source lock; individual checkpoint receipts bind payload/config/token ABI and do not independently attest the source implementation.
