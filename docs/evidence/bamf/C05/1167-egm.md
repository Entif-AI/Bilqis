## Disposition

The design was revised in place to resolve every finding:

- batch issued `ModelOutput`, not `NeuralProposal`; proposal minting remains lazy under C04's live request;
- B11 owns one shared scalar/batched row decoder and `_FORWARD_ISSUANCE` path;
- resource capacity uses compiled-position width with >96-position scalar fallback;
- task-owned single-row batches are explicitly bound before refinement;
- shared hidden is sliced to the exact original row length;
- transient row/padding/config/source/receipt composition and row-index custody are explicit;
- the first task-owned `AtlasFeatureArtifactOwner` is reused only after exact common feature/schema/extent checks;
- exact test and timing-evidence paths are named;
- batching is restricted to Factory contexts with non-empty route holes, no cached compositions/fallback/refiner, and default routes;
- only side-effect-free compatibility/resource predicates select scalar fallback; validation/execution failures propagate;
- same-device current-B11 peak memory must be measured against the active allocation budget and the cap reduced if necessary.

## Implementation-discovered B11 padding delta

The first real pinned four-row Factory execution exposed a narrower pre-existing B11 seam that the design review could not see from static contracts alone: `FrameEncoding.global_seeds` lawfully pads mixed-width rows to a common tensor width, while `FrameEncoding.features` retains each row's natural compiled-position length. `source_depth_select_with_diagnostics()` required those feature rows to already equal padded width, so a mixed-width shared producer failed before depth selection.

The design was amended to zero-pad only the feature-factor tail beyond each row's natural compiled positions. A targeted fresh-context EGM delta review checked `depth_selection.py` and `frame_encoder/execution.py` and returned **Blocker 0 / Major 0 / Nit 0**. Real positions retain their existing factor validation and vectors; padded positions contribute exact zero feature vectors. Scalar and same-width behavior are unchanged.

## Post-implementation drift reconciliation

Fresh-context EGM drift review compared the approved design with the live implementation. It identified and drove three implementation/proof corrections before turn-in:

- B11 row decode now independently revalidates producer source, feature schema, compiler config, source projection, generation, compiled-row custody, and the task route/refinement plan before forward issuance.
- `contexts_for()` validates every requested `TaskGoal` against the canonical Factory instrument before cache lookup, so an altered goal cannot reuse a cached context merely by preserving `goal_id`.
- The focused regression suite now exercises mixed real compiled widths, >96-position scalar fallback through `evaluate_cases()`, deterministic bounded chunk splitting, fail-closed compatibility errors, task-plan custody rejection, and repeated cached-goal drift rejection.

After those repairs, the only remaining drift finding was a stale focused-suite count in the timing receipt. The final focused run completed with **10/10 tests passing in 497.432s**, and `1167-timing.md` was refreshed to match. **Drift status: NO_DRIFT.**
