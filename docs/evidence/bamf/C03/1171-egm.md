## Initial review

The fresh review failed the first design with **3 Blockers / 4 Majors / 1 Nit**.
Implementation did not begin while those findings were unresolved.

The material findings were:

1. A digest-only planning-generation guard would lose same-manifest B13 custody drift
   detection because the current deep validator authenticates bundle bytes plus
   DataPlane node/object/CAS state.
2. A captured C09 registry digest would not detect replacement of the live
   host/provisioned trust root during the planning transaction.
3. The mutable candidate-frontier manifest is a self-consistency record, not proof
   that the pinned builder produced a cold cached directory. Reuse needed provenance
   outside the mutable cache.
4. The original performance framing overstated existing repeated work: parameter-tree
   generation hashing and accepted feature authentication were already once per
   planning transaction; repeated B13/C09 currentness was the material target.
5. The live unified base introduced #1174 prepared-row/source-prefetch semantics that
   #1171 must preserve.
6. The exact release invalidation identity and measurable definition of “material”
   latency improvement were underspecified.
7. Reuse-miss exceptions needed an explicit fail-closed taxonomy.

## Repairs

The design was revised before implementation to:

- add an append-only workstation DataPlane planner-frontier trust receipt keyed by
  exact builder digest + canonical source-input digest +
  `ExecutableFactoryRelease.release_sha256`;
- require a trusted cached directory to revalidate against the ordinary frontier
  loader and the immutable receipt, with deterministic output conflict failing closed;
- add a B13-owned process-live currentness witness that deep-validates once and then
  covers bundle-tree identity plus every external DataPlane dependency consumed by
  `validate_bamf_bundle_custody()`:
  - manifest node via `get_node()`;
  - every sidecar `object_sha256` via `get_object()`;
  - current tensor `object_sha256` via `require_file_object()`;
- add a C09-owner witness for the exact fixed host/provisioned trust-root file selected
  by custody, with no caller-selected path;
- preserve pointer/acceptance, parent, correction-frontier, feature, executable-release
  and per-offer source/row/currentness checks;
- preserve #1174 `prepared_rows` / `prepared_source_rows` behavior;
- make B13/C09 repeated deep work the explicit optimization target while retaining the
  already-once generation-hash/feature-auth behavior as regressions;
- identify the exact Factory release invalidator;
- predeclare a three-sample median timing protocol with both >=20% and >=2.0 s required
  improvement and identical selected priority/visit; and
- classify only documented `CANDIDATE_FRONTIER_*` validation failures as reuse misses.

The factual source-offer size was also corrected from 356 to 357 lines. The extraction
into a dedicated planning-generation owner remains mandatory before additive logic to
avoid the repository's >360-line structural interrupt.
